Product contract

How it works

PulseGuard is a governed neuro-symbolic loop over a bundled Flask demo service. It is not a general SAST product and does not scan repositories you supply.

Propose, then falsify

A language model may propose an exploitability verdict, a patch, a PoC input or a service topology. Deterministic checks then try to falsify that proposal: taint traces, sanitizer facts, re-scan after patch, regression tests, evidence-citation checks, counterfactual consistency, a PoC witness, and (where extracted) a z3 validator proof. A check may veto a neural conclusion. It never invents a false-positive on its own.

Hard evidence and analysis limits

Before any model call the system builds a Hard Evidence Block. Only items that make a claim receive an E-id. The model must cite those ids.

  • E1 — rule and source location
  • E2 — dataflow from source to sink
  • E3 — sanitizer rules on the path
  • E4 — exposure / blast-radius context
  • E5 — PoC witness (observable deviation before the patch, none after)
  • E6 — validator model (z3 sat / unsat)

A check that ran but could not decide receives an L-id in a separate ANALYSIS LIMITS section. The UI labels it “Not covered (analysis limit)”. That is not “no risk” and it is not a pass. Citing an L-id invalidates the verdict.

Governance tiers

Verified P2/P3 findings may be approved automatically. P0/P1 always need a human. If the event bus is stale or stalled, policy is advice-only: no automatic approval. Remediation produces a bundle (patch + PR description), not a merge to a real Git remote.

REPLAY and LIVE

REPLAY is the public default. The container verifies a sha256 manifest, seeds the case store from a recorded run, and makes no new model calls. Approve, reject and rollback are simulated and labelled. LIVE runs locally or behind a token on Render, scans only the bundled demo service, and loses results on restart.

Playground

The Playground accepts a pasted snippet, size-capped, and never executes or stores it. Language tiers decide what the analysis can prove:

  • Full analysis (Python) — Guard, Semgrep, Bandit, Hard Evidence E1–E6, z3, adjudication, citation checks and the z3 veto. This is the only tier that can confirm a finding with sanitizer facts and constraint solving.
  • Grammar-level analysis — partial coverage (Java, JavaScript, TypeScript, Go, C#, C, C++, SQL) — tree-sitter excerpt, Semgrep taint where rules exist, E1/E2 when the source call is confirmed on that line. Sanitizer recognition and z3 are not available. For C and C++, memory-safety classes (buffer overflow, format string) are not analysed yet.
  • LLM-only — advisory, no hard evidence (COBOL, SAS, PL/SQL, parse failures) — the model sees an excerpt with no E-items. The verdict is advisory and would not reach remediation.

When model keys or the daily budget are missing, static analysis still runs and is labelled as such.
